# CLAUDE.md

이 문서는 `serasome` 개인 블로그(VitePress) 프로젝트를 관리하고 새 게시물을 작성할 때 반드시 준수해야 할 규칙(Harness)입니다.

## 1. 개발 및 빌드 명령어

작업 디렉토리: `frontend/`

- 개발 서버 구동: `npm run docs:dev`
- 프로덕션 빌드 테스트: `npm run docs:build`

## 2. 카테고리 및 구조

- 프로그래밍/개발: `docs/programming/` (하위 기술별 디렉토리)
- IT 기기 리뷰: `docs/it/` (기기/모델별 디렉토리)

게시물 생성 시 반드시 `docs/.vitepress/config.mts`를 읽고, 해당 카테고리의 `items` 배열에 다음 형태로 사이드바를 수동 등록할 것:

```ts
{ text: '제목', link: '/경로/' }
```

## 3. 게시물 스타일 가이드

- **어조**: 정중한 구어체 종결어미(~합니다, ~습니다, ~해 봅시다)를 사용하며, 필자의 1인칭 경험담 narrative("제 기억 속에...", "고민을 한창 하던 중에...")를 자연스럽게 녹여낼 것.
- **Frontmatter**: `title`, `titleTemplate`, `description`을 필수 포함할 것.
- **요약 레이아웃**: 본문 시작 전 `::: info` 또는 `> [!info]` 컨테이너를 사용하여 핵심 요약을 제공할 것.
- **이미지 및 캡션 문법**: 반드시 아래 표(Table) 형식을 따르고 지정된 CSS 클래스를 부여할 것.

```md
| ![alt](./images/name.png){:class='image'} |
| :-----------------------------------------: |
|       _출처 : 설명{:class='caption'}_       |
```

## 4. 콘텐츠 템플릿 유형

- **트러블슈팅형** (`resolves/*`): 문제 발견 → 원인 추적 narrative → 해결 코드 및 명령어. 코드 블록은 라인 강조 구문(예: ` ```js{6,16} `)을 사용할 것.
- **소개/리뷰형** (`it/*`): 상단 마크다운 스펙표 → 기능별 상세 섹션 + 출처 캡션 반복 패턴.

## 5. 배포 규칙

- `main` 브랜치 푸시 시 GitHub Actions로 S3 + CloudFront에 자동 배포됨.
- git 커밋 및 푸시는 독단적으로 수행하지 말고, 반드시 사용자의 최종 diff 확인 및 승인을 거칠 것.
